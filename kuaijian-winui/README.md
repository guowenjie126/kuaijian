# 快剪 Windows C# WinUI

这是按《快剪-CSharp-WinUI-功能规格.md》实现的 Windows 原生版本，目标是保持 macOS 版的功能、交互和视觉结构。

## 已实现

- 手机号注册、验证码登录、密码登录、找回密码和 Windows 凭据管理器 Token 持久化；启动恢复遇到 HTTP 401 或明确的失效 Token 错误码时清除旧凭据，密码重置成功也会删除旧登录凭据；密码登录默认隐藏并提供显式显示/隐藏切换；认证输入有限长校验，服务端认证响应限制 1 MiB，账号 ID 校验后才用于本地目录
- 文本、网址、图片、富文本和文件路径剪贴板捕获
- 剪贴板来源优先按 Windows clipboard owner 识别并显示应用产品名；读取不到时回退进程名或“来源未知”
- 复制已有记录、问答答案和计算历史使用与 Windows 剪贴板序列号绑定的一次性通知抑制；仅忽略对应的应用内写入，未到达或过期的旧通知不会吞掉用户后续复制
- 剪贴板监听异常会在剪贴板页面显示可读状态，不会静默丢失全部功能
- 分类、搜索、复制、收藏、置顶、备注、删除和图片预览；网址记录单击复制、双击或通过右键菜单打开默认浏览器（仅 HTTP/HTTPS）
- “文本”分类只显示纯文本，不把文件/目录剪贴板记录混入；图片和 RTF 按 SHA-256 内容指纹去重（不受临时路径影响），同一纯文本的不同 RTF 格式会保留，重复捕获的图片/RTF 临时资源会清理
- 图片分类页支持 70%–220% 缩放、百分比显示、重置和缩略图联动；预览弹窗先按可用视口和原始像素尺寸等比适配（不放大小图），再支持 50%–400% 缩放；调整窗口尺寸会重新适配基准尺寸
- 问答库支持新建、编辑、删除、启用开关和列表搜索（问题、答案、别名、关键词），以及 CSV/JSON 导入导出；CSV 往返保留逗号、双引号和多行字段，损坏引号会明确拒绝；批量导入按 ID 合并后仅写盘一次
- 可选的全局问答助手：后台复制问题后按完整问题、别名或任一关键词匹配并回写答案；模糊匹配只提示候选；可按来源应用限制，默认关闭，不会自动发送
- 问答页离开后不会继续响应隐藏页面的剪贴板变化；用户编辑中的问题及离开后草稿不会被后台剪贴板初始化覆盖，仍可通过“读取剪贴板”主动替换；读取失败和复制失败均显示页面内反馈
- 计算器按规格保持五行按键布局；括号可用 Shift+9/Shift+0 输入并参与运算；支持键盘输入、运算优先级和错误反馈；除数为 0 时结果为 0；最多保存 30 条历史，点击历史项复制结果且不重新捕获为新剪贴板记录
- HTTP/HTTPS 下载任务、进度、取消、打开目录、持久化；有强 ETag/Last-Modified 且服务端支持 Range 时，断网/取消后可继续下载，否则安全地从头开始；续传片段和下载目录位于不同磁盘时先复制到目标卷临时文件再原子提交；同时下载数可设为 1–5（默认 2），超限任务排队且可取消；下载完成行为可按账号设置为无操作或在资源管理器中定位文件（不会自动打开/运行下载内容）；异步任务固定绑定创建时的账号，账号切换后不会把旧任务记录写入新账号；临时文件原子预留并发防撞名，提交时遇到同名文件会安全改名且不覆盖
- 下载页多次打开时共享任务进度和状态，切换页面后不会显示停滞的旧进度
- 下载任务的排队、下载中、完成、失败和取消状态使用 WinUI 原生 SymbolIcon，并为状态图标提供可访问名称
- 多站点下载：安装包内置 Windows x64 `yt-dlp.exe` 与 FFmpeg Essentials `ffmpeg.exe`；支持站点按主域/子域边界匹配，避免相似域名误走 yt-dlp；重定向输出强制 UTF-8，保留中文标题和错误信息；每个账号任务复用独立 staging 目录，取消/重启后复用 yt-dlp 默认 `.part`/分片续传，成功后再跨卷安全提交并清理 staging
- 浏览器登录状态仅在用户明确选择 Chrome、Edge 或 Firefox 后，由多站点下载调用 yt-dlp 本机读取；普通 HTTP/HTTPS 直链不使用浏览器身份；Cookie 不上传、不写入快剪账号数据文件；读取失败显示 yt-dlp 诊断信息
- 取消多站点下载时终止整个 yt-dlp 子进程树，并等待进程退出及标准输出/错误回调完成后再清理任务临时目录
- 账号隔离的本地数据及用户偏好（问答助手、剪贴板保存策略、下载目录/并发、互传接收目录、窗口偏好）；旧版全局偏好首次登录时迁移到该账号；开机启动、全局快捷键和更新提示保持机器级。剪贴板云端每 15 秒拉取/上传，按 ID 合并并保留尚未上传的本机记录；图片、RTF 和文件/目录资源路径留在本机；云请求流式读取并限制 8 MiB；更新清单只接受 Windows x64 HTTPS `.exe`、有效版本和 SHA-256，下载限长并校验后才启动安装器
- 剪贴板删除保存在当前设备/账号的原子写入 ID 清单中，后续云端轮询不会让本机重新显示；清单按账号隔离，损坏时备份原文件并提示；由于服务端暂无删除 tombstone，该删除不会同步到其他设备，并会明确提示这一限制
- 用户 JSON 数据损坏时保留原文件、创建带时间戳的损坏备份并在剪贴板页提示，不静默清空后覆盖
- 手动更新检查会同步全局更新状态与设置图标红点，避免保留过期提示
- 设置弹窗按规格提供账号、保存、下载、隐藏、更新五个分区；全局问答助手开关和来源限制嵌入保存分区；另含收缩栏、窗口置顶、托盘、开机启动和 Ctrl+Shift+V 全局快捷键；可选启用“关闭到托盘”，仅已登录窗口会隐藏，托盘菜单的显式退出仍结束应用
- 保存设置可控制剪贴板类型、配置 50–500 条历史上限（默认 200，置顶项优先），并查看/打开当前账号隔离的数据目录
- 窗口位置和尺寸持久化；登录窗口与主界面分别记忆，收缩栏退出时保存并恢复收缩前的窗口边界
- 多显示器下按虚拟桌面边界恢复窗口，并让收缩栏出现在当前窗口所在显示器的工作区右侧
- 登录页优先显示嵌入的快剪品牌图标，资源加载失败时回退到文字标识
- 旧版历史导入支持 CopyQ `exportJSON()` 单条 MIME 对象和官方 `copyq_items` 多条包装（文本、HTML、RTF、图片和标签；即使没有纯文本也保留富文本记录）、JSON 数组及常见 `items/history/records/data` 包装、CSV、文本、UTF-8/UTF-16（含大小端 BOM）和 GZip 探测；压缩输入文件和解压后内容均限制 64 MB，防止高压缩比文件耗尽内存；检测到 CopyQ 私有二进制 `.dat` 时会明确提示先导出 JSON，不会把二进制误导入为乱码
- 团队页面保留规格定义的第二阶段占位，不伪造未接入的团队能力
- 互传已有 transport-agnostic 本地收发核心：发送端提供稳定元信息、可重试 8 MiB 分块读取及按服务端确认持久化的发送检查点；发送协调器只在收到匹配的分块确认后推进检查点，并要求远端确认完整 SHA-256 校验和文件保存后才清理。接收协调器通过流式 transport 按预期长度读取至多 8 MiB，不缓冲异常超长响应；先持久化分块、校验哈希并无覆盖落盘，再确认服务端。ack 响应丢失时通过账号本地 outbox 重试而不重复下载/保存，且可按已提交文件恢复提交与 outbox 之间的崩溃窗口。发送/接收进度按实际已确认块字节数累计，支持稀疏短尾块；续传协调器从待处理游标扫描，避免每块重扫已完成前缀。发送检查点、接收暂存和 ack outbox 均位于账号隔离目录；因服务器设备注册/绑定/收件箱/ack 路由与字段契约尚未提供，UI 仍明确显示不可用，不展示模拟设备或任务

## Windows 构建环境

- Windows 10 1809 或更高版本
- .NET 8 SDK 或更新版本（当前工作站使用 .NET SDK 9.0.318 构建 net8.0 目标）
- Visual Studio 2022 可用于 IDE 开发，但不是命令行构建的必要条件；本工程通过 `dotnet` SDK 和 NuGet 包构建
- Windows App SDK 1.6（由 `Microsoft.WindowsAppSDK` NuGet 包固定版本并还原；自包含发布不要求目标机预装该运行时）
- Inno Setup 6（生成安装包时需要）

开发构建：

```powershell
dotnet restore
dotnet build -c Debug -p:Platform=x64
dotnet run -c Debug -p:Platform=x64
```

由于 Windows App SDK 的 XAML 编译器不接受当前中文工程路径，发布脚本会自动复制到 ASCII 临时目录后构建：

```powershell
.\build-installer.ps1
```

输出：

```text
installer\KuaiJian-<版本号>-Windows-x64-Setup.exe
```

## 自动更新发布

仓库根目录的 `.github/workflows/windows-release.yml` 会在 `kuaijian-winui` 有新提交时，在 Windows Runner 上构建 x64 安装包并生成 `latest.json`。Windows 客户端读取公开的 `https://api.kuaijian.jingronghao.com/updates/windows/latest.json`；安装包可以放在官网的 `/downloads/` 目录，清单中的 `downloadURL` 指向对应安装包。设置页会校验 SHA-256 后下载并启动安装程序。

发布新版本前，请先把 `installer.iss` 中的 `MyAppVersion` 从例如 `0.4.0` 改为新的三段版本号，再提交到 `main`；也可以在 GitHub Actions 手动运行工作流并填写版本号。相同版本的 Release 不会被覆盖。

由于 `runtime-tools\yt-dlp.exe` 和 `runtime-tools\ffmpeg.exe` 不提交到仓库，GitHub Actions 自动构建的安装包默认只包含基础 HTTP/HTTPS 下载能力；需要多站点下载时，应在 Windows Runner 的构建前安全注入这两个已核验的运行时文件。

更新清单和安装包必须公开访问，不能让客户端携带 GitHub Token。当前 Windows 客户端已经固定读取 API 的 Windows 专用清单；该接口目前能公开返回空清单，发布 Windows 版本后需要将其更新为真实版本信息。

运行无第三方测试框架的回归验证（剪贴板捕获策略与来源快照、账号目录隔离、用户 JSON 损坏备份和并发原子保存、问答/计算器、导入导出、HTTP/yt-dlp 续传、跨磁盘原子提交、下载完成行为、历史保留、安全边界、同步合并、删除清单、下载并发和子进程取消）：

```powershell
dotnet run --project .\verification\KuaiJian.WinUI.Verification.csproj -c Debug -p:Platform=x64
```

## 当前边界

- 团队空间、问答云端同步、图片云端同步和多设备冲突处理需要后端 API 扩展。
- 已增加“互传”导航和真实空状态页面；接收目录可本地选择，设备绑定、发送、收件箱和分块传输仍未接通服务端，页面会明确显示不可用，不展示假设备或假任务。
- 私有旧版 `.dat` 二进制格式需要真实样本才能完成字段级适配；当前已支持 JSON、CSV、文本、UTF-8/UTF-16 和 GZip 探测。
- 发布签名和安装包签名需要正式证书。
- 传统 `System.Windows.Automation.AutomationElement.FromHandle` 只能看到 WinUI DesktopChildSiteBridge 的宿主 Pane，不能据此判断页面为空白；Windows App SDK WinApp UI Automation 已枚举到登录页控件，但当前桌面截图通道超时，尚未完成目视验收。登录后页面还需真实账号交互测试。
